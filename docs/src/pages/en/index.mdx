<SectionHeading id="what-it-does">What DeltaRecon does</SectionHeading>

<Prose>

You know the analysis of change from the balance sheet and from Solvency II: a reconciliation from last year to the current <span data-no-term>state</span>, step by step. DeltaRecon takes as its steps the <Term id="revision">revisions</Term> of the versioned valuation program. Each revision is one change. Between <Term id="release">release</Term> N and the <Term id="state">state</Term> N+1 DeltaRecon computes states, compares them, and attributes the <Term id="deviation">deviation</Term> in a <Term id="quantity">quantity</Term> to the single revisions that cause it.

Every result comes from computations and comparisons that give the same result each time. DeltaRecon uses no agents.

The picture shows the example of the quick start on the <Term id="reference-model">reference model</Term>: the state N+1 lies {facts.revisions} revisions after release N, and {deviating} of them deviate in the <Term id="bruttobeitrag" />, the gross premium.

</Prose>

<SectionHeading id="what-you-need">What you need</SectionHeading>

<Prose>

A computer with Windows or Linux. You download one archive and unpack it. Nothing is installed: the package holds everything it needs, including the reference model, a term life insurance with {facts.modelPoints} <Term id="model-point">model points</Term>. The reference model demonstrates the mechanics and is not a valuation model; its portfolio is synthetic and holds no client data.

</Prose>

</Prose>
