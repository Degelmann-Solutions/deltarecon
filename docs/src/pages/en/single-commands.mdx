The guided demo of the <a href={pageAddress(quickStart, 'en')}>{quickStart.name.en}</a> runs the commands of the quick start for you, apart from `replay`. <Prose>

The examples of this page are the commands that the guide `README.txt` in the package folder lists; the example of `walk` is the one exception, the guide does not list it. They write to the folder `runs` in the package folder, and they build on each other in the order of this page: `request` writes what `run` reads, and so on. The folder `runs` is a free choice; the files of a run may lie in any folder.

No command overwrites an existing file. A command whose output exists already does not start. To repeat a calculation, give it an output that does not exist yet.

<SectionHeading id="request" command="request"><code translate="no">request</code>: say what is to be computed</SectionHeading>

<Prose>

`request` writes a run request: the file that says what is to be computed. It names the release completely, that is the code, the parameters and the input data, each by the full name of its revision, and the version of the engine. It also names the model points to run. `request` computes nothing; `run` does.

For the <Term id="reference-model">reference model</Term> a release is a revision of the history that the package holds in the folder `delib-history`. You name it by its full or abbreviated hash, by a branch, by a tag or by `HEAD`; a suffix such as `HEAD~1` is not read. The request then holds the full hash.

The example writes the request for release N of the quick start.

</Prose>

<SectionHeading id="run" command="run"><code translate="no">run</code>: compute a request</SectionHeading>

<Prose>

`run` checks the request, restores the files of the named revision to a scratch folder, projects the selected model points and evaluates the five built-in checks of the model for each. It writes its files beside the request.

A run ends with one of four outcomes. `succeeded`: there are results. `failed`: a model point raised an error, a check is false, or a result is not a finite number; there are no results. `error`: the request was accepted, but the engine could not restore or read the state; there are no results. `rejected`: the request broke a rule, and nothing ran. The record is written for every outcome, except for a file that cannot be read as a run request.

</Prose>

<SectionHeading id="replay" command="replay"><code translate="no">replay</code>: repeat a recorded run</SectionHeading>

<Prose>

`replay` checks a record, repeats its run in the new folder `replay/` beside the record, and compares the recorded run with the repeated one. It prints whether the run is reproduced, how many <Term id="value">values</Term> deviate, and the paths of its files.

The outcome is `reproduced_exactly`, `reproduced_at_decimals` or `reproduced_within_tolerances`, depending on what the <Term id="tolerance-profile">tolerance profile</Term> holds, or `not_reproduced`. If the record or a file that it lists was altered after the run, the replay is rejected and writes nothing.

</Prose>

<SectionHeading id="compare" command="compare"><code translate="no">compare</code>: compare two runs</SectionHeading>

<Prose>

`compare` compares the two runs that a compare request names, value by value, under the tolerance profile of that request. When the two runs can be compared, it writes the values that deviate and a signature table, which has one row per quantity that deviates.

You will rarely start it yourself: `replay`, `regression`, `walk` and `search` write and run their compare requests themselves. The file `replay-compare.request.json` that `replay` writes is such a request. This page therefore gives no example command.

`compare` takes no option, apart from the path of the compare request.

The files of `compare`:

</Prose>

<RowList>
  <Row name="The compare request" tag="reads">The path that the command is given, and with it the two runs that the request names.</Row>
  <Row name="The result" code="compare.result.json" tag="writes">Written beside the request. It lists the model points that deviate.</Row>
  <Row name="The values that deviate" code="compare.deviations.csv" tag="writes">One row per value above the tolerance. Written when the two runs are compared.</Row>
  <Row name="The signature table" code="signature-table.json" tag="writes">Per quantity that deviates: in how many model points and values, in which periods, and the largest increase and decrease. Written when the two runs are compared.</Row>
  <Row name="The record of the comparison" code="compare.run-record.json" tag="writes">Written when the release of both runs can be read.</Row>
</RowList>

<SectionHeading id="regression" command="regression"><code translate="no">regression</code>: check a recorded run against a newer revision</SectionHeading>

<Prose>

`regression` takes the record of a run that succeeded, a full run without enabled changes. It computes the newer revision that you name on the same model point table and for the same model points as the recorded run, and compares the two runs. In the new run the code and the parameters are those of the newer revision, and the input data are those of the recorded run.

It reports that nothing deviates above the tolerance, or it prints every model point that deviates and the signature table. When the new run fails, ends with an error or is rejected, nothing is compared.

In the example the newer revision is the state N+1 of the quick start. The command ends with exit status 1 there, by design.

</Prose>

<SectionHeading id="derive" command="derive"><code translate="no">derive</code>: list the changes between two recorded runs</SectionHeading>

<Prose>

`derive` takes the records of two runs that succeeded, both full runs without enabled changes, the older one first. It reads the history of the model between their two revisions and writes the change manifest: one change per revision on the main line of the history, after the older revision and up to the newer one, in the order of the history. A branch that was merged is one change, the merge.

Each change carries its <Term id="class">class</Term>: data, parameter, code, several of them or none. What differs between the two records and belongs to no revision, the version of the engine, is named as the remainder and belongs to no change. The command prints the changes and the remainder.

Two revisions that do not lie on one main line, also two records in the wrong order, are refused, and nothing is written. The same two records give the same file, byte for byte.

</Prose>

<SectionHeading id="walk" command="walk"><code translate="no">walk</code>: compute every state between two recorded runs</SectionHeading>

<Prose>

`walk` attributes the deviation between two recorded results to the revisions between them. It takes the same two records as `derive`, which must hold the same model points, derives the change manifest and computes every state: state 0 is the older revision, and one further state follows after each change. It checks state 0 against the older record and the last state against the newer one; each must reproduce its record, under the tolerance profile or, without one, exactly.

It then compares each state with the state before it. Its result says for each change and each quantity whether the change contributes, and gives the signed sum of the differences and the sum of their absolute values. Where the walk compares exactly, the signed sums of a quantity add up exactly to the deviation between the two records.

The input data move with the states when each record names its own revision as its input data. They stay at the older revision when both records name the same one, as the record of a `regression` does; that is the case in the example. A state that does not run is reported, and the next state that runs carries its change as well.

The walk is the reference result, and it computes the most: one state per change and one more, {counts.states} in the example. <a href={pageAddress(works, 'en')}>{works.name.en}</a> sets it beside the search.

</Prose>

<SectionHeading id="search" command="search"><code translate="no">search</code>: find the changes that deviate, with fewer computations</SectionHeading>

<Prose>

`search` takes the same two records as `walk` and makes the same checks before it computes. It needs no walk. It computes state 0 and the last state, checks them against the two records, and then halves the history: it judges a stretch of the history by comparing the states at its two ends, does not divide a stretch whose ends agree, and attributes a deviation to a stretch that holds a single change. <a href={pageAddress(works, 'en')}>{works.name.en}</a> explains the method and its limits.

You can narrow the search to a target with `--quantity` and `--periods`. Only the values of the target are then judged and summed. The example searches in the <Term id="bruttobeitrag" /> in the periods 0 to 59, the first five projection years.

The result names the target, the stretches that were judged, the changes that contribute with their sums, and the findings, among them a stretch that is “<Term id="not-resolved">not resolved</Term>”. It also counts the states that the search computed, those that a walk would compute, and those it saved. The exit status is 0 when both ends ran and are reproduced.

</Prose>

<SectionHeading id="quickstart" command="quickstart"><code translate="no">quickstart</code>: the guided demo</SectionHeading>

`quickstart` is the guided demo of the <a href={pageAddress(quickStart, 'en')}>{quickStart.name.en}</a>. It runs `request`, `run`, `regression`, `derive` and `search` on the two revisions of the examples above, without `replay`, explains each of its four steps and waits for Enter before each. It always computes with the reference model. Its search compares under the tolerance profile `tolerance-bruttobeitrag.json` of the package; its regression compares exactly.

You start it through its starter, which changes to the package folder, hands its options on to `quickstart` and ends with its exit status:

<SectionHeading id="shared-options">{sharedName}</SectionHeading>

<Prose>

Six options mean the same in every command that takes them. The section of a command names those that it takes.

</Prose>

<RowList>
  <Row name="The tolerance profile" code="--tolerance" option>A file in JSON that sets for each quantity how far a value may deviate. Without it the comparison is exact: there is no tolerance profile that holds by default. The package holds one in its folder `profiles/`, `tolerance-bruttobeitrag.json`: it lets a change of the <span lang="de">Bruttobeitrag</span> of at most one cent per model point and month pass and compares every other quantity exactly. `compare` takes the tolerance profile of its request.</Row>
  <Row name="The number of worker processes" code="--workers" option>How many processes project the model points of a state at the same time: a whole number of at least 1. Without it the number is the one that the environment variable `DELTARECON_WORKERS` names, else one per processor. The number changes no file that a command writes.</Row>
  <Row name="The engine" code="--engine" option>The engine to load, as `MODULE:CLASS`. Without it the command takes the engine that the environment variable `DELTARECON_ENGINE` names, else the reference model.</Row>
  <Row name="The folder of the engine" code="--engine-path" option>A folder that is put on the import path before the engine is loaded, so that a module in it can be named. Without `--engine` and without this option the command takes the folder that `DELTARECON_ENGINE_PATH` names.</Row>
  <Row name="An option of the engine" code="--engine-option" option>An option that the engine reads, as `KEY=VALUE`. You may give it several times, each key once. The reference model takes the key `path` alone, the way it computes: `path=export`, the default, through the export of the model that modelx writes, or `path=modelx`, through modelx itself. A run never falls back to the other way.</Row>
  <Row name="The folder of the histories" code="--repositories" option>The folder that holds what the engine restores a release from; for the reference model the folder that holds `delib-history`. In the package the launcher sets it to the package folder, so you need not give it.</Row>
</RowList>

<Callout tag="Hint" title="The engine options are for an engine of your own">

Without `--engine` and without the variable `DELTARECON_ENGINE` every command computes with the reference model, and you need none of the three engine options to follow this page. With an engine of your own, DeltaRecon reaches it through its <Term id="adapter">adapter</Term>, which `--engine` and `--engine-path` select. <a href={pageAddress(enginePage, 'en')}>{enginePage.name.en}</a> describes what an engine has to provide.

</Callout>
