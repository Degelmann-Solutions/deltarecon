DeltaRecon – geführter Quick Start

Die Vorführung vergleicht zwei Stände des Referenzmodells delib-history, einer
Risikolebensversicherung mit 350 Modellpunkten: Release N und den Stand N+1, 32 Revisionen später.
In vier Schritten zeigt sie, wie DeltaRecon eine Abweichung zwischen zwei Releases findet und auf
die Änderungen zurückführt, die sie verursachen. Die Vorführung legt ihre Dateien in einem eigenen
Ordner an, und alle Befehle laufen dort:
  cd runs/quickstart-20261112T110800Z

Schritt 1 von 4: Release N rechnen

Zuerst schreibt request einen Rechenauftrag nach --output. Er hält fest, welcher Stand gerechnet
wird (--revision, die Revision fa36857), welchen Namen dieser Stand trägt (--label N) und unter
welcher Kennung der Auftrag läuft (--run-id run-n-full). Name und Kennung sind frei gewählt und
erscheinen in den späteren Vergleichen wieder. Ohne --subset gilt der Auftrag für alle Modellpunkte
des Bestands, mit --subset nur für die genannten. Dann rechnet run diesen Auftrag und hält das
Ergebnis mit seiner vollständigen Herkunft fest: Code, Parameter und Bestandsdaten. Dieses Ergebnis
ist die Referenz, gegen die jeder weitere Schritt prüft.

Befehle:
  deltarecon request --revision fa368575a66d97c94e96dffc62b273ec95511b12 --label N
      --run-id run-n-full --output release-n/request.json
  deltarecon run release-n/request.json

Release N ist gerechnet: 350 Modellpunkte, 80.580 Ergebniszeilen. Dateien in release-n: results.csv
(die Ergebnisse), response.json und run-record.json (der Nachweis, womit was gerechnet wurde).

Schritt 2 von 4: Regression gegen N+1

regression nimmt den Nachweis des Laufs von Release N aus Schritt 1 (release-n/run-record.json) und
rechnet mit --revision den neueren Stand N+1, die Revision 887b718. Er rechnet auf denselben
Bestandsdaten und für dieselben Modellpunkte wie Release N und vergleicht beide Ergebnisse Wert für
Wert. Ohne --tolerance vergleicht er exakt: Jede Abweichung zählt. Den Lauf von N+1 und den
Vergleich schreibt er in den Ordner --output, den Lauf in dessen Unterordner run. So zeigt sich, ob
und wo sich die Ergebnisse der beiden Releases unterscheiden. Eine Abweichung ist hier erwartet;
der Befehl meldet sie mit dem Exit-Status 1.

Befehl:
  deltarecon regression release-n/run-record.json
      --revision 887b7181d22550eda2fb52fa1a6bd77376d4eb2e --output regression

Die Regression zeigt eine Abweichung: 408.762 Werte in 350 Modellpunkten weichen ab. Ein Wert ist

Schritt 3 von 4: die Änderungen zwischen N und N+1

derive nimmt den Nachweis von Release N aus Schritt 1 (release-n/run-record.json) und den Nachweis
von N+1 aus Schritt 2 (regression/run/run-record.json) und liest daraus, welche zwei Revisionen
gerechnet wurden. Dann liest es die Versionsgeschichte zwischen diesen beiden Ständen, listet jede
Änderung einzeln auf, in der Reihenfolge, in der sie gemacht wurde, und schreibt dieses
Änderungsverzeichnis nach --output. Jede Änderung ist eine Revision und wird eingeordnet: Daten
(der Bestand), Parameter (Tabellen wie Storno- oder Kostensätze), Code (die Rechenvorschriften)
oder nichts davon (zum Beispiel nur Dokumentation).

  deltarecon derive release-n/run-record.json regression/run/run-record.json --output changes.json

Schritt 4 von 4: die Ursache im Bruttobeitrag suchen

Welche der 32 Änderungen verursachen die Abweichung im Bruttobeitrag (--quantity Bruttobeitrag) in
den ersten fünf Projektionsjahren (--periods 0-59, eine Periode je Monat)? search nimmt dieselben
beiden Nachweise wie Schritt 3: release-n/run-record.json und regression/run/run-record.json. Es
rechnet nicht jeden Zwischenstand, sondern halbiert die Versionsgeschichte, bis jede Abweichung
einer einzelnen Änderung zugeordnet ist. Als Abweichung zählt eine Änderung des Bruttobeitrags um
mehr als einen Cent je Modellpunkt und Monat; das legt das Toleranzprofil fest (--tolerance). Mit
--target-only rechnet es die Zwischenstände nur für den Bruttobeitrag in diesen Perioden und ohne
die Modellprüfungen; die beiden Endstände rechnet es vollständig. Das Ergebnis schreibt es in den
Ordner --output. Die Bestandsdaten bleiben auf dem Stand von Release N.

Befehl:
  deltarecon search release-n/run-record.json regression/run/run-record.json
      --quantity Bruttobeitrag --periods 0-59
      --tolerance ../../profiles/tolerance-bruttobeitrag.json --target-only --output search
