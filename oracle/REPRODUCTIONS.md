The present computation walks the reference chain of `delib-history` from its start commit `fa368575a66d97c94e96dffc62b273ec95511b12`, which holds the data, parameters and code of release N with three fixes that keep every result bit for bit, to `887b7181d22550eda2fb52fa1a6bd77376d4eb2e`, 32 commits later. Those commits repeat, one by one and with the same messages, the first 32 commits of the earlier chain from release N to `ab5dc79`; that chain's last three commits changed no result and are not repeated. The computation ran in the working tree of deltarecon on the branch that lays the new chain, before its commit, with the local clone of `delib-history` that had fetched the new chain; it did not use fresh clones. The files the run reads, the code of deltarecon, the requests and the tolerance profile, are those of the commit. Its requests are the bytes `deltarecon request` writes for the two revisions on the default computation path, the export, and equal the archived requests apart from `contract_version`, the engine version and the revision. Each of its 24 signature tables, with `contract_version` set back to `2.0`, hashes to the digest the archived `SHA256SUMS` lists: state k of the new chain gives the bits of state k of the earlier chain, and the step numbers, run ids and labels are unchanged. The signed sums per quantity add up exactly to the deviation between the two ends. Durations: the two runs about 4 s each, the walk of 33 states about 3 minutes.

The computation of 2026-10-25 walked the earlier chain from release N, `b64334e09613c45a7a12468dfddc0d9ec47819bb`, to `ab5dc790f5bed52f94a4c8fb8d6b710bc31f0a33`, 35 commits on the model before the fixes. It used fresh clones of deltarecon and of `delib-history`. The deltarecon clone held `a9464ac`, an earlier form of `793c035` whose tree differs from it only in the README, the "Changes from 2.0" text of `contracts/v3/README.md` and the module docstring of `degelmann/deltarecon/__main__.py`, none of which the run reads. It gave the same 24 signature tables and the `walk.result.json` hash `1ee1e006e36a323164c8a95be1de483a864e86231c0e4e65c3b6c145f7d00003`. That hash was replaced when the oracle moved to the new chain, because the walk result names the revisions of the states and holds the hashes of their responses. Durations: the two runs about 9 s each, the walk of 36 states about 9 minutes.

The computation of 2026-10-24 on the modelx path used fresh clones of deltarecon at the commit that pins Python 3.14.9 and of `delib-history`, with the requests of the modelx engine version. It gave the same 24 signature tables and the `walk.result.json` hash `909577ffd3ce23f3eab26cc70e52490617dac984986cd223ca5d347432ca023f`. That hash was replaced when the oracle moved to the export path, because the walk result holds the hashes of the run responses and each response names the engine version, which names the computation path. Its durations: the two runs about 90 s each, the walk of 36 states about 77 minutes.
