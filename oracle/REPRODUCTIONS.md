# Reproductions of the oracle

The first row is the run that computed the published hashes under contract version 3.3. Every later row is one run of the README section "Reproduce the reference attribution" from fresh clones, checked with `sha256sum -c` against `SHA256SUMS` in this folder. The published hashes are never changed to match a run; a run that differs is recorded here with the differing files and the cause.

The run used a clean worktree of deltarecon at the commit above and the local clone of `delib-history`; it did not use fresh clones. Its requests are the bytes `deltarecon request` writes for the two revisions on the default computation path, the export, and equal the requests of the 3.1 archive apart from `contract_version`. It ran the commands of the README section "Reproduce the reference attribution" from `mkdir` to the walk, with `--repositories` naming the local clone. Each of its 24 signature tables, with `contract_version` set back to `3.1`, hashes to the digest the `SHA256SUMS` of the 3.1 archive lists, with `contract_version` set back to `3.0`, to the digest the `SHA256SUMS` of the 3.0 archive lists, and, rebuilt in policy months and with `contract_version` set back to `2.0`, to the digest the `SHA256SUMS` of the 2.0 archive lists. Every listed hash is new, because each table and each response the walk result references carries `3.3`. Durations: the two runs about 5 s and 3 s, the walk of 33 states 2 minutes 45 s. The opt-in reproduction `DELTARECON_ORACLE=1 uv run pytest tests/test_oracle.py` was not run after the renewal: its walk is the same command sequence on the same code, and the hash check and the archive checks ran on the folder of this run.
