# Reproductions of the oracle

The first row is the run that computed the published hashes under contract version 3.0. Every later row is one run of the README section "Reproduce the reference attribution" from fresh clones, checked with `sha256sum -c` against `SHA256SUMS` in this folder. The published hashes are never changed to match a run; a run that differs is recorded here with the differing files and the cause.

The present computation used fresh clones of deltarecon and of `delib-history`. The deltarecon clone held `a9464ac`, an earlier form of `793c035` whose tree differs from it only in the README, the "Changes from 2.0" text of `contracts/v3/README.md` and the module docstring of `degelmann/deltarecon/__main__.py`, none of which the run reads. Its requests are the bytes `deltarecon request` writes for the two revisions on the default computation path, the export, and equal the archived requests apart from `contract_version` and the engine version; they were copied into the `oracle/` folder of the clone before the README commands ran once. The commit that publishes them adds only the requests, the hash of `walk.result.json`, the text of this file, the README text on the computation and its durations, and `tests/test_oracle.py`, none of which the run reads besides the requests. Each of its 24 signature tables, with `contract_version` set back to `2.0`, hashes to the digest the archived `SHA256SUMS` lists. Durations: the two runs about 9 s each, the walk of 36 states about 9 minutes.

The computation of 2026-10-24 on the modelx path used fresh clones of deltarecon at the commit that pins Python 3.14.9 and of `delib-history`, with the requests of the modelx engine version. It gave the same 24 signature tables and the `walk.result.json` hash `909577ffd3ce23f3eab26cc70e52490617dac984986cd223ca5d347432ca023f`. That hash was replaced when the oracle moved to the export path, because the walk result holds the hashes of the run responses and each response names the engine version, which names the computation path. Its durations: the two runs about 90 s each, the walk of 36 states about 77 minutes.

An earlier computation under Python 3.12.13, with deltarecon at commit `426d1b6a197c2da426c048678a1a21794a4b6b23` and the engine version `modelx 0.33.0, pandas 3.0.6, numpy 2.5.3, Python 3.12.13`, gave the same 24 signature tables and the `walk.result.json` hash `867081d325a053653f15e3bfa8e0cc9cfa06931fecd72594ca8b4143e9b2e0cc`. That hash was replaced when the interpreter moved to Python 3.14.9, because the walk result holds the hashes of the run responses and each response names the engine version.
